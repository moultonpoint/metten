# EGM maintained-repository coverage

## Overview

This is the entry point for documentation drift checks across **the entire maintained repository**, including shared files and newly added components. Established 13 November 2026 for [issue #26](https://github.com/moultonlavah/metten/issues/26) against foundation `b1eb58c25fed5a2970bd5c40db9c05f673ff8d71`; Connor authorized expanded inspection on 14 November and full-repository coverage for every daily run on 20 November. The [expanded report](2026-11-14_DRIFT_REPORT.md) preserves the earlier passes and their limits. This map documents existing behavior, not retrospective approval of every implementation choice.

The recurring **Daily Drift Report** follows [the full-repository daily route](#daily-full-repository-audit) and [the report request](#expanded-drift-report-request). There are no issue-based exclusions. The ownership inventory below is a cross-check, not a fixed limit on coverage; new maintained paths must also be accounted for. A separately requested narrower audit must state its coverage limits.

The [product specification](../../METTEN_DESIGN_DRAFT_2026-11-12.md) and accepted ADRs remain authoritative. Issues #1–#4 supply completed-slice context: MIT licensing, a controlled persisted session, isolated dummy-credential integration and controlled rules/local immutable versions. The [issue #4 evidence index](../verification/issue-4.md#current-evidence-index) identifies the operative approved contract and latest completion/review corrections. Determine implemented scope from current contracts and evidence, including later source and controlled paper additions. Unimplemented future product features are not regressions in completed slices. GitHub owns current issue status; historical verification records are not a second tracker.

### Issue #4 ownership and authority

The [strategy guides](../strategies/README.md) own `docs/strategies/*` and the shared `examples/learning.json` teaching file. The engine, desktop, interface and regression contracts above cover all current shared-file strategy changes, including `src/view.ts`, `tests/refresh.test.mjs`, CI, the root README and glossary. Daily audits include issue #4 and all later maintained additions. Read shared files in full; the former foundation-only projection filter does not apply.

`docs/proposals/**` contains historical intake, drafts, reviews and source captures. Follow the evidence index to [the operative approved design](../proposals/issue-4-egm/strategy-rules-design.md); do not treat every archived proposal or continuation prompt as a requirement. New maintained paths or behavior without documented ownership are findings or explicit coverage gaps, never silently excluded.

### Other exclusions

Ignored private research/planning and runtime data, secret values/private credential records, `.git/`, dependency installations, generated `src-tauri/gen/`, `target/`, `dist/`, `.scratch/` and temporary verifier resources are not maintained implementation inputs. Follow `.gitignore`; do not read secret/private records to perform drift reporting. Include hidden maintained configuration such as `.github/` and `.gitignore` in the coverage check.

## Invariants

- Trace each in-scope component to a contract and compare in both directions: documented behavior versus current code, and code versus documentation coverage. A new undocumented file or behavior is a finding even if the existing contracts still match.
- Source-grounded observations do not override the product specification, accepted ADRs or issue acceptance criteria. Record contradictions rather than blessing current code by copying it into a README.
- Preserve the distinction between effective control, accepted requests and confirmed saved state; dummy credential proof is not real account/provider integration. No paper/live behavior or release readiness is established here.
- Historical records retain original results and limitations. Later finished checkpoints supersede earlier incomplete states; old CI wording is not current remote status. No fresh test result is implied by a source inspection.

## Side Effects

Drift checking reads maintained source/docs and writes a dated Markdown report. It does not modify source, credentials, runtime state, requirements or inspected contracts. Fixing a discrepancy is separate bounded work. No scheduled job or new dependency is required.
