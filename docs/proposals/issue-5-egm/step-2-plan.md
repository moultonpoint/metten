## Atomic evidence correction

Original evidence: `strategy.rs` rejects a second binding ID per transaction in `Pending.member_bindings`; each completed transaction then triggers condition evaluation. Splitting value and validity across same-time transactions can expose the old value or temporarily unavailable new value. Public `phase1_atomic_updates_do_not_expose_intermediate_equal_time_values` establishes that same-time transactions are observably distinct. Issue #4's historical evidence at line 405 correctly records pair rejection under its then-supported single-change contract. This step deliberately supersedes that one restriction. Link the new pair regression/accounting evidence from the issue-5 index and code map so an agent cannot mistake the historical rejection for the current rule; leave issue #4's record unchanged.

Allow exactly one `Observation` OR `Resynchronize`, optionally paired with exactly one `Validity`, for a binding in the same normalized transaction. Standalone validity remains legal. A gap may coexist with changes to different bindings; it cannot share its own binding with any other change in that transaction. Reject two observations, two resynchronizations, two validities, two gaps, observation plus resynchronization, and gap-plus-other for the same binding before mutation, preserving the existing evaluator error `unregistered_binding` for forbidden duplicate combinations. Document that established code's duplicate-member meaning in the engine contract and issue-5 evidence instead of inventing a new error. No strategy-JSON grammar, arithmetic, timing or checkpoint-meaning change; normalized evidence admission is explicitly extended by this pair rule.

Process all admitted transaction members before conditions. For a paired validity with a reason or a deadline at/before the transaction time, finalize the pair by clearing the evaluator's retained value before conditions, regardless of member order, while preserving its observation high-water mark. A later standalone lease cannot expose the suppressed value. Fresh initialization/observation plus independently valid evidence is required. Keep this finalization bounded and sliced; account its member tracking and cleanup in the changed branch proof. This new pair-specific behavior does not change the established semantics of unrelated standalone lease renewal. The source owner likewise marks invalidated bindings as requiring initialization and refuses lease-only revival. Test invalid pair in both orders → advance a cell → valid standalone lease → still unavailable → genuine fresh value plus validity → usable; replay of the invalid pair's observation number cannot supply the fresh observation.

The standalone source invalidation rule has its own public test: usable input → `invalidate` with no known historical interval → lease-only `apply` returns `invalid_request` and emits no renewal → source remains unavailable → verified current-generation initialization plus valid evidence restores present state only. Also test the positive path: an initialized, usable binding with no intervening loss accepts a substantiated future-deadline lease-only renewal, emits Validity, adds no observation and remains usable without reinitialization. Document the deliberate seam: evaluator standalone `Validity{reason:Some}` retains its raw value while revoking eligibility; renewal does not erase historical cell invalidity or certify coverage. The unchanged `review_historical_cells_retain_same_time_invalidity` test must still assert unavailable affected historical cells after renewal. Current point-value reads and historical cell reads have different requirements; that history test is not evidence that renewal always restores usable data. SourceState refuses lease-only revival after actual source loss; test both this policy and the unchanged evaluator seam. Do not broaden pair-specific clearing to every standalone validity. `after_checkpoint_update` keeps its established meaning of a later accepted genuine observation identity, independently of current price freshness; preserving its high-water mark is intentional, not permission to emit an observation with unproved genuineness. Assert that distinction and unchanged current-ask eligibility through the public tests rather than adding a new availability condition to the operator.

Use the existing per-transaction binding-membership tracking with a finite member-kind mask rather than a new scan of prior changes. Track one entry per concrete binding (at most 128), and preserve sliced cleanup. Update `tree_work`, actual `HeapBytes`/metadata reservation and the branch/helper derivation for the changed entry type; inspect Rust 1.100.0 B-tree layout assumptions already documented in [issue #4 evidence](../../verification/issue-4.md#current-evidence-index). Do not reuse the old tree charge if its value type changes. Retain 4096-primitive slice accounting and the shared 8 MiB ingress reservation. Record the derivation in the step-2 evidence record. Run affected existing independent work/allocation probes; a test score does not replace this argument. Stop and report a blocker if the narrow correction cannot fit those bounds without broader evaluator redesign.

Mask lifetime is explicit: keep validation's existing per-transaction draining. During application, build a separate bounded mask for only the current transaction as its members are applied; track value-kind/validity/invalid-paired-deadline bits, then finalize those bindings incrementally before conditions and drain that mask with the same sliced discipline. Do not retain masks for every admitted transaction or rescan prior transactions. Charge both simultaneous validation/application maps and all finalization lookups/cleanup in the updated metadata and work derivation. The extra current-transaction bookkeeping has the concrete purpose of member-order-independent invalid-pair clearing after validation summaries have been drained; it is not a generic event framework.

## Owned state, identity and trusted evidence

The source owner retains only source/subscription facts, per-binding last display value and provenance, current deadline, capability/coverage frontier summaries, accepted observation high-water marks, generations and current/next preparation. It stores no raw frames, level books, complete historical intervals or price series. Provider adapters later own reconstruction, provider-specific identity/deduplication and precise unit conversion. The existing evaluator owns historical cells and strategy state.

In the controlled source pipeline, SourceState is the sole emitter of Validity for its bindings; the evaluator's deadline is a derived copy and never feeds back as authoritative source validity. Direct evaluator-only tests keep their existing controlled-evidence interface. Source/evaluator divergence on rejected evidence follows the stated invalidation protocol rather than an assumption that two copies cannot disagree.

The fixed logical sources are Kalshi, BRTI, Coinbase and Kraken. Kalshi and BRTI share a connection; continuity scopes distinguish book subscription, trades, BRTI, metadata, Coinbase trades and Kraken trades. A normalized envelope separately preserves source/binding identity, connection/subscription generation, bounded provider identity where supplied, provider UTC time, monotonic local receipt time and local accepted order. Provider clocks never order different sources. Use checked counters; exhaustion stops the affected owner rather than wrapping.

Controlled times are u64 monotonic milliseconds since Go. The envelope explicitly includes `completed_frontier_ms`, supplied by the controlled consumer from the last completed evaluator Decision's evaluated_through_ms under the one-outstanding-batch contract, alongside accepted `at_ms`, local receipt elapsed time and received-through watermark from one clock, separately from provider UTC. SourceState does not inspect evaluator internals or invent this frontier. Ordinary acceptance requires receipt <= at_ms, at_ms >= the last accepted time and completed_frontier_ms, and at_ms <= received_through_ms. An effect's target is its last accepted time (or the explicit clock-advance target); transactions have at_ms within [completed frontier,target], in nondecreasing time and strictly increasing checked owner-assigned transaction-number order. Repeated time never collapses genuine events. Coverage/gap ends cannot exceed the received watermark. Validate these facts before ordinary state mutation and preserve the engine's own validation. Process a verified market boundary at exactly open_ms before advancing the evaluator clock past it; a timer handled after open is display-only and emits no backdated boundary. Registering/initializing a source after open cannot enter the missed window. Add a source/evaluator timeline for on-time boundary, ordinary advance past open, then late verification with no boundary; at_ms below supplied completed frontier, decreasing accepted time or impossible watermarks return `invalid_order` before mutation without contaminating another binding.

Capabilities are separate for current validity, genuine observations and complete history, with finite unavailable reasons corresponding to U1–U7. A received event cannot enable its own capability. Production-profile facts remain unavailable as established in the source guide. Tests can supply explicitly controlled capability, lease and coverage facts through the trusted Rust interface; that does not upgrade a provider profile or prove entitlement/rights. Reference-dependent paths remain unavailable under U5; ask-only paths do not gain a reference dependency.

An initialization with a mapped value emits `Resynchronize`, never an observation. Genuine normalized observations carry monotone numbers for the exact binding; high-water marks survive recovery. Equal-price new numbers may count. Same-number same-value replay does not count; same-number conflicting value invalidates the affected evidence. Adapter-level rules for older provider identities, BRTI conflicts, book quantity-only changes and Kraken gaps remain provisional; this module must not invent them. Over-precision input is rejected with existing `Decimal::parse` before normalized acceptance; the trusted caller reports invalid mapped evidence through invalidation so an older usable value is not retained as healthy. Range-invalid typed values also revoke affected usability.

Malformed/unregistered/wrong-identity input is rejected before changing an unrelated binding. Authenticated evidence of loss, contradiction, invalid value or denied access revokes the affected state before publication. Finite failure codes: `invalid_request`, `identity_mismatch`, `obsolete_generation`, `invalid_order`, `invalid_value`, `inconsistent_evidence`, `resource_limit`, `stopped`. Unavailable, awaiting, stale and explicit access refusal remain distinct snapshot reasons. Messages contain no upstream or submitted text.

## Generations and completed results

Invalidation increments the relevant generation before accepting further ordinary events. Shared-book loss revokes both retained books and successor readiness. Connection loss revokes all its streams, including BRTI for Kalshi. Logical disconnect affects only that logical source's subscriptions. Every retained binding needs current-generation initialization before it becomes usable again; reconnect or acknowledgment alone cannot restore it.

Every concrete binding has a generation that is advanced when it is revoked, in addition to its stream/connection generation. Stamp entries include both plus the binding's registration incarnation. A new owner has a unique checked process-local owner identity; a registration incarnation comes from a checked owner-local counter. Retirement makes the old binding unknown; reusing its numeric binding ID gets a different incarnation, never a matching old stamp. Counter exhaustion fails closed. `is_current` returns false for unknown/retired bindings, a stopped or different owner, a missing dependency, or any generation/incarnation/market-revision mismatch. Lease expiry is separate: a matching stamp does not certify freshness. No unbounded tombstone set is retained.

A stamp contains every binding/stream generation used by the claimed result, plus relevant market identity and metadata/preparation revision. Check all entries before using a completed result; checking only the event-triggering stream is insufficient. Exclude unrelated optional sources. The controlled consumer supplies the explicit complete dependency set for its test strategy; automatic extraction of per-decision dependencies and production publication are later integration work, not a new evaluator result protocol in step 2. Tests exercise two-source dependencies and an independent path. No claim of production candidate fencing is made. `Pending` never yields a usable decision. Stop rejects every subsequent apply or completion; a later explicit connection belongs to a new owner, not revival of a stopped instance.

## Market windows and bounded ownership

Use bounded clones/normalized capacities so tiny inputs with huge spare capacity cannot inflate retained state.
