## Gate 1 — finite commands and safe ownership

### Wire contract

Use flat tagged request objects, matching the existing manual native decode pattern. The following are exact allowed key sets; no additional key is accepted. `source` is one of `kalshi`, `brti`, `coinbase`, `kraken`.

| Command | Accepted request shapes |
| --- | --- |
| `sources` | `{operation:"snapshot"}`; `{operation:"details",source}`; `{operation:"inspect",version_id}`; `{operation:"connect",source}`; `{operation:"disconnect",source}` |
| `provider_credential` | `{operation:"status",provider:"kalshi",environment}`; `{operation:"remove",provider:"kalshi",environment}`; `{operation:"save",provider:"kalshi",environment,key_id,private_key}`; replace has the same material fields as save |

`environment` is the finite demo/production enum and must equal the native application's selected environment; it is never an item selector or permission to switch hosts. Establish one native environment at initialization and use it for both Transport and credential operations. For the controlled candidate use Demo and the validated disposable store/controlled transport; production activation/owner setup is not exercised or accepted in this stage. No URL/environment-variable host override, persistent preference or environment-switching UI is added. Display the selected environment so demo data cannot be mistaken for production.

Reject raw/nonobject bodies, unknown/missing keys, wrong types, extra nested objects and oversized inputs with fixed sanitized failures before copying submitted strings. Enforce a 256-KiB encoded request ceiling with a bounded counting serializer/borrowed walk that stops at the ceiling; do not allocate a complete oversized encoded clone just to measure it. Tauri has already parsed `InvokeBody::Json`; this bounds our command work, not framework-wide raw IPC allocation. Strict allowed scalar fields also bound traversal. IDs are canonical positive decimal strings with no leading zeros, sign, exponent or whitespace, at most 19 digits and within positive i64 for SQLite versions. Source counters/generations/sequences use checked u64 and canonical decimal strings; never convert through JavaScript Number. Credential IDs: 1–128 printable ASCII bytes; PEM: at most 16 KiB; existing parser supports Ed25519 PKCS#8 and 2048-bit RSA PKCS#1/PKCS#8. Validate material before revocation. No secret Debug/serialization or framework errors that quote it.

Return tagged source outcomes and a finite code/message failure projection in the native bridge. Map all existing provider failures, including Busy, Missing, AlreadySaved, invalid credential, Denied, StillStopping, capacity, deadline, protocol, storage/unavailable and ambiguous mutation. Unknown failures get a fixed fallback. Do not forward server text, native error details, submitted bytes or private PEM. Credential status returns Missing or Saved with nonsecret key ID/key type; mutation success reflects confirmed readback, not request submission. Coinbase/Kraken acquire no credential forms.

Snapshot and details each have a complete serialized maximum of 256 KiB. Count encoding before returning; on overflow return finite capacity failure, never truncate required state or falsely return a partial healthy snapshot. Use the existing shared 32-MiB native Memory owner for response/pending serialization ownership; include encoding and old/new response overlap in the simultaneous-ownership inventory. Retain at most 32 compact transitions, aggregate repeated reasons, and store no raw payload archive. Do not add a log service or SQLite table.

Snapshot includes owner/revision, UTC snapshot observation time and monotonic age basis, selected environment, current/next exact identities/schedules/preparation, all four logical states, binding values/units/side/source/provider identity/provider UTC/age, separate current/observation/history capability and readiness/reasons, and bounded progress/request/control/retry counters. Age is receipt age, not proof of upstream freshness. Preserve decimal values as exact strings. Large owner/revision/order/sequence/generation/counter fields are strings. A latest view missing at startup yields a local disconnected/awaiting result, never an implicit Connect. Recheck worker, provider, stream and schedule fences at projection; keep unrelated sources readable if one is revoked. Do not serialize a retained stale view as current merely because the connection flag is open.

`details` is scoped by logical source; native code selects only the retained current/next market IDs for book/trade details and labels each. The screen cannot request arbitrary tickers. BRTI raw/average/count/window and spot maker/taker quantities remain labeled details. `inspect` uses the existing saved-detail read, validates its exact immutable JSON with `ValidatedStrategy`, and derives requirements; unsupported/not-found/storage failures are finite. Return no copied strategy document or raw provider data. Reuse strategy admission for that blocking lookup so Quit waits for it; do not add another storage owner or new public strategy command shape.

### Mutation and failure ordering

1. Decode/size-check, then admit one source/credential mutation. Competing mutations return Busy rather than accumulating spawned native tasks. Also enforce one local source read per main window natively, releasing its guard on every outcome; competing snapshot/details/inspect calls return Busy instead of queuing retained responses. Pure snapshot/details reads never wait on a Keychain prompt or provider join. Credential status is an explicit native credential operation, not part of the one-second source poll.
2. Check general quitting and the persistent source-stopping latch. Move Coordinator/credential ownership into admitted blocking work under short locks; retain an admission guard/complete notification that Quit can await. Never hold a Workspace/shared lock across Security calls, signing lookup, network work or joins. Restore all handles on success, error, unwind or canceled caller; use the existing guard pattern and bounded ownership, not detached work. Reject queued work again after admission if Quit won.
3. Connect reads the native fixed credential only for Kalshi/BRTI and only after explicit action. Reuse `with_signer` and existing owned signing types. Missing/refused/invalid credential gives no socket; save/status/inspect/refresh never connect. Public spot sources use no credential. Repeated Connect is idempotent for the same admitted logical subscription, not a second task. Native startup/reopen remains disconnected.
4. Keep a four-member desired set in the existing source handle/worker path. Kalshi adds book/trade/metadata; BRTI adds index discovery/value on the same socket. Metadata needed by a retained contract source stays until its consumer disconnects; BRTI alone must not imply contract discovery. Adding the second Kalshi consumer reuses the existing task/socket. Update the provider service's desired membership via the existing bounded control/watch machinery; mandatory outcomes are not silently coalesced away.
5. Disconnect revokes that logical source's stream gates immediately, ahead of ordinary queue work, then removes its subscriptions and publishes the result. Last logical consumer stops/joins that provider. Disconnecting Kalshi retains BRTI if requested; disconnecting BRTI retains contract subscriptions. A shared socket failure invalidates both. Other providers stay independent. Fence the old receive/subscription incarnation so late work cannot revive disconnected state. Never stop/restart the shared socket just to fake scoped disconnect.
6. Replace/remove reuse `Credentials::change`: validate, revoke and stop/join shared Kalshi/BRTI, then fixed-item read/mutation/readback. Invalid new material leaves current state unchanged; admitted replacement/removal failure preserves appropriate stored state but leaves both logical sources stopped until explicit Connect. Stop timeout retains handles and refuses mutation. Ambiguous outcome blocks Connect until fixed-item reconciliation establishes the record. No mutation auto-reconnects. Save is absent-only and does not stop an existing source merely because it returned AlreadySaved.
7. Quit latches/revokes source work first, including pending fixture dispatch, without waiting for a prompt. Serialize owner transfer with command admission: Quit records the stop request immediately even if a mutation currently owns Coordinator; that operation observes it before any start and restores handles before Quit joins. Keep one absolute five-second source phase covering sockets/worker/receiver, no locks across waits. Unconfirmed completion retains handles, refuses engine save and reports stopped/unconfirmed. Later Quit checks the same handles. Wait for admitted inspection and native credential work before stopped-save; native prompts remain noncancelable. Connect may recover only after observed old completion and an inactive general Quit. No guard reset clears the source-stop latch or reconnects.

Keep a narrow revocation handle to the same Coordinator fences/stop signals available in Workspace before moving Coordinator into native work. This is shared cancellation authority over existing owners, not a second connection-state owner. Quit uses it synchronously; it must not need the credential worker to return before revocation becomes effective. The admitted operation rechecks that persistent stop request before starting any fresh generation. Test Quit while status/Connect is blocked in the controlled native-store seam. Source deadline expiry never cancels an OS credential call or permits cleanup/save with unfinished ownership.

Register only these two new commands in `build.rs` and the invoke handler, generate their permission TOMLs with Tauri, and grant them only to the existing local main window. Keep CSP and filesystem/shell/network grants unchanged. Test the actual Tauri authority resolver for local-main allow, other-window and remote-origin denial, and invented commands; checking a JSON permission list alone is insufficient.

Gate completion: command tests exercise the real owner with controlled transports/stores, demonstrate logical sharing/revocation and zero requests from local reads, and leave foundation/session/strategy/storage/dummy contracts intact.
