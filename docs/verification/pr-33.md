## Provenance and source review

GitHub's upstream tag API resolves `actions/setup-node` v7.1.0 directly to
`949feb2413d6458794dcd2491c4babbbce0c15c1`; the commit API reports a valid
signature. The [release](https://github.com/actions/setup-node/releases/tag/v7.1.0)
is immutable. Compared against the old pin
`49933ea5288caeca8642d1e84afbd3f7d6820020`: reviewed the changed-file inventory,
action manifest, package metadata and complete action-owned `src/` changes,
including installer selection, authentication, cache restore/save and errors.
Inspected the corresponding bundled setup/cache-save entry-point tails and ESM
package markers. This is a bounded compatibility/provenance review, not an
exhaustive audit or reproducible rebuild of the bundled dependencies.

- The manifest has no nested action references. Main remains
  `dist/setup/index.js`; successful-job cleanup remains `dist/cache-save/index.js`.
  Internal execution changes from Node 20 to Node 24 and ESM. The upstream
  [README at the pin](https://github.com/actions/setup-node/blob/949feb2413d6458794dcd2491c4babbbce0c15c1/README.md)
  requires runner 2.327.1 or later; the successful Mac run used 2.338.2.
- Explicit `node-version: 24` still takes precedence over version-file parsing.
  New installed-version validation fails on a mismatch; manifest retrieval now
  retries three times. No mirror or version-file input is used here.
- Explicit `cache: npm` takes precedence over new package-manager auto-detection.
  The cache remains keyed by OS, architecture, package manager and lockfile hash;
  it caches npm's cache directory, not node_modules. An exact hit skips saving.
  Save errors still fail the action except the existing uncaught-exception
  warning path; a cache service refusal returning -1 remains a non-save result.
- The removed `always-auth` input and dummy `NODE_AUTH_TOKEN` fallback affect
  registry authentication only. This workflow supplies neither registry-url nor
  registry credentials, so it never enters that configuration path. The default
  GitHub token input for Node downloads is unchanged. Permissions stay
  `contents: read`; no additional credential or permission is introduced.
