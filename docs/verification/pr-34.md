## Provenance and bounded source review

The upstream [v7.0.1 tag API](https://api.github.com/repos/actions/checkout/git/ref/tags/v7.0.1)
resolved directly to the pinned commit. GitHub's
[commit API](https://api.github.com/repos/actions/checkout/commits/3d3c42e5aac5ba805825da76410c181273ba90b1)
reported signature verification `verified: true`, reason `valid`.
Reviewed the [old-to-new inventory and source diff](https://github.com/actions/checkout/compare/11d5960a326750d5838078e36cf38b85af677262...3d3c42e5aac5ba805825da76410c181273ba90b1),
including `action.yml`, main/post entry routing, input handling, source fetching,
ref verification, Git commands, credential setup/removal and unsafe-PR handling.
This is a compatibility and provenance review, not a complete audit of bundled
JavaScript or transitive dependencies.

- The manifest switches the action runtime from Node 20 to Node 24; both main
  and post remain `dist/index.js`. There are no nested action references.
  ESM import changes retain failure reporting and post-job cleanup routing.
- Default checkout still uses the workflow repository and event ref/SHA, with
  depth one. Changed tag fetching verifies the requested commit; this workflow
  supplies no custom ref, tags, submodules or alternate repository.
- The [upstream runtime requirements](https://github.com/actions/checkout/blob/3d3c42e5aac5ba805825da76410c181273ba90b1/README.md#checkout-v5)
  require runner 2.327.1 or newer. The observed hosted macOS-15 runner was
  2.338.2. No container action or authenticated Docker Git commands are used.
- Default persisted authentication now uses a separate generated file under
  `RUNNER_TEMP`, referenced through Git `includeIf`, rather than storing the
  token directly in repository Git config. Placeholder replacement avoids
  passing the token as a process argument. Post-job cleanup removes matching
  includes and the temporary credential file; failed removal can warn rather
  than fail the job, so passing application checks alone is insufficient proof
  of cleanup. The observed cleanup log has no such warning.
- Events remain `push` and `pull_request`, with `contents: read`. No custom
  token or SSH key, unsafe checkout override, privileged event or permission
  expansion is introduced. The unsafe-fork guard applies to customized
  checkout under `pull_request_target`/`workflow_run`; those triggers are absent.
- Node 24 for application checks, Rust 1.100.0, all check commands and the
  packaged Mac build remain unchanged. No engine/resource-proof assumption or
  application credential/storage/IPC path changed in this pin substitution.
